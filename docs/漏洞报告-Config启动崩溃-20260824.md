# 漏洞报告：dsh-turn-cost 0.2.0 Config 误用 zod 语法致 dsh web 启动崩溃

- **日期**：2026-08-24
- **仓库**：`<repo-root>`（npm 包 dsh-turn-cost，本机部署 0.2.0）
- **严重度**：**高**——单个插件的 Config 声明错误导致整个 dsh web 无法启动（cordis 插件树整树拒载）
- **状态**：**应急修复已落地**（本地提交 `9f01cb8`，未推送）；本报告供 codex 复核修复并补齐回归防护

---

## 1. 现象

`npx @deepseek-ai/dsh web` 启动即崩，进程退出。错误链：

```
Error: dsh: plugin tree failed to load: failed to apply loader entry include (cordis:include):
  failed to import loader entry turn-cost (dsh-turn-cost): z.string(...).optional is not a function
TypeError: z.string(...).optional is not a function
    at <static_initializer> (...\profiles\web\node_modules\dsh-turn-cost\lib\index.js:133:54)
```

崩点是类静态字段（static initializer），发生在**模块 import 阶段**——cordis 加载器连实例化的机会都没有，直接把整个插件树标记失败，dsh web 随之退出。稳定复现（机主连试两次，报错逐字节一致）。

## 2. 根因

`lib/index.js:17` 的 `z` 来自 **`@deepseek-ai/schemastery`（3.18.1），不是 zod**：

```js
import z from "@deepseek-ai/schemastery";
```

schemastery 的 schema 对象**没有 `.optional()` 方法**。实测其 string schema 的方法集为：

```
~standard, toJSON, set, push, i18n, extra, required, disabled, collapse, hidden,
loose, deprecated, experimental, pattern, simplify, toString, role, default, link,
comment, description, max, min, step
```

schemastery 的对象字段语义与 zod 相反：**缺省即可选，要必填用 `.required()`**。0.2.0 新增配置字段时按 zod 习惯写成：

```js
static Config = z.object({ ratesPath: z.string().optional() });   // ← 崩在这
```

已用真实 schemastery 3.18.1 验证正确写法的行为：

| 输入 | `z.object({ ratesPath: z.string() })` 结果 |
|---|---|
| `{}` | ✅ 通过（字段缺省可选） |
| `{ ratesPath: "x" }` | ✅ 通过 |
| `{ ratesPath: 1 }` | ✅ 正确拒绝（类型检查仍在） |

## 3. 已实施的应急修复（变更记录 #4，B 轻流程）

- `lib/index.js:133`：`z.string().optional()` → `z.string()`，并加注释说明 schemastery 语义、防止再犯。
- 全库排查 `.optional() / .nullable() / .parse() / .safeParse()` 等 zod 风格调用：**仅此一处**。
- 部署副本 `<dsh-home>\profiles\web\node_modules\dsh-turn-cost\lib\index.js` 已与源码同步（diff 归零）。
- `docs/DEVELOPMENT.md` 踩坑清单新增条目：「Config/schema 只能用 schemastery 语法；改 Config 后必须真实启动一次 dsh web 验证」。
- `docs/方案-dsh-turn-cost.md` 追加变更记录 #4（事故/根因/修复/复检/遗留观察全记录）。

## 4. 已做过的复检

## 5. 留给 codex 的待办（回归防护，按优先级）

1. **复核应急修复**：确认 `z.object({ ratesPath: z.string() })` 在 schemastery 语义下与意图完全一致（可选字段、类型校验保留），并检查 `Config` 消费方对 `ratesPath === undefined` 的分支是否覆盖。
2. **补 host 侧冒烟测试（本次事故暴露的测试盲区）**：现有 22 项测试只覆盖 fold.js 纯函数与 client 无头冒烟，**没有任何用例 import host 端 `lib/index.js`**——Config 在 import 阶段就崩，单测自然拦不住。建议新增一个冒烟用例：以真实 `@deepseek-ai/schemastery` 断言 `TurnCostService.Config` 可定义、可校验 `{}` 与含 `ratesPath` 的配置。仓库当前无 cordis/schemastery 依赖，需要想一个不引入重型依赖的方案（例如仅对 Config schema 做独立导出后单测，或 devDependency 只装 schemastery）。
3. **加一条静态防线**：在 CI 或 pre-commit 里 grep 禁用模式（`\.optional\(\)`、`\.nullable\(\)`、`\.parse\(`、`\.safeParse\(` 出现在 `lib/index.js` 的 schema 上下文），防止 zod 肌肉记忆再次流入。
4. **发布决策**：修复提交 `9f01cb8` 与 0.2.0 功能提交 `a0a0c3c` 均在本地未推送；npm 0.2.0 也未发布。**0.2.0 若按现状发布会把崩溃带给所有用户**，发布前必须含本修复；推送与 npm 发布待机主指令（npm 2FA 需机主本人）。
